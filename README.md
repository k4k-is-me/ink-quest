# InkQuest — Narrative Quest Engine

Fabric-мод для Minecraft 1.20.1. Система квестов, ориентированная на нарративный геймплей.

InkQuest занимает нишу, которую не закрывают FTB Quests или BetterQuesting: это инструмент для авторов карт, которым нужен контроль над историей, а не таблица прогресса. Квест здесь — сюжетное событие с развитием: он проходит этапы, может завершиться успехом, провалом или быть пропущен. Вся конфигурация ведётся через JSON-датапаки и команды — без GUI-редактора и без зависимостей от сторонних модов.

## Структура квеста

Квест состоит из **этапов**, каждый этап содержит **одну обязательную задачу** и любое число **необязательных**. Этапы проходятся последовательно: следующий открывается только после завершения обязательной задачи текущего.

**Исходы квеста:**
- `success` — все обязательные задачи выполнены успешно или пропущены (но не все пропущены)
- `failure` — хотя бы одна обязательная задача провалена; квест завершается немедленно
- `skipped` — все обязательные задачи пропущены

Два типа квестов:
- **Статические** — описаны в датапаке, загружаются вместе с миром
- **Динамические** — создаются командами во время игры, хранятся в сохранении мира

## Быстрый старт

### Создание квеста через датапак

Создайте файл `data/<namespace>/quests/<id>.json` в датапаке:

```json
{
    "version": 3,
    "variant": 1,
    "title": "Побег",
    "description": "Здесь больше нельзя оставаться, но как же выбраться?",
    "tasks": {
        "push_the_lever": {
            "title": "Найти и опустить рычаг, открывающий люк",
            "description": "Когда один из стражей выходил, мне удалось услышать щелчок в дальней части комнаты"
        },
        "look_for_survivors": {
            "title": "Узнать что стало с выжившими",
            "description": "Нужно обыскать камеры, может удастся найти ещё кого-нибудь"
        }
    },
    "stages": [
        ["push_the_lever", "look_for_survivors"]
    ]
}
```

Первый элемент каждого этапа — обязательная задача, остальные — необязательные.

Поля `version` и `variant` обязательны. Текущая версия формата — `3.1` (`version: 3`, `variant: 1`).

### Создание квеста командами

```
/quest new example:escape "Побег" "Здесь больше нельзя оставаться, но как же выбраться?"
/quest modify example:escape tasks add required push_the_lever "Найти рычаг" "..."
/quest modify example:escape tasks add optional look_for_survivors "Найти выживших" "..."
```

### Выдача и управление

```
/quest give PlayerName example:escape
/quest give PlayerName example:escape pin    # выдать и сразу закрепить в HUD
/quest pin PlayerName example:escape         # закрепить в HUD
/quest complete PlayerName example:escape task push_the_lever success
/quest drop PlayerName example:escape
```

## Условия выполнения

Задачи могут завершаться **автоматически** по условиям (только для задач из датапаков). Условия проверяются каждый тик у задач активного этапа **всех** активных квестов игрока — закреплённых и незакреплённых.

Условие задаётся отдельно для успеха и/или провала:

```json
{
    "tasks": {
        "my_task": {
            "condition": {
                "success": { "type": "..." },
                "failure": { "type": "..." }
            }
        }
    }
}
```

### `score` — достижение значения scoreboard

```json
{
    "type": "score",
    "objective": "oak_logs_mined",
    "criterion": "minecraft.mined:minecraft.oak_log",
    "target": 5
}
```

Отображает прогресс-бар в HUD. Поддерживает восходящие и нисходящие условия (если `initial > target` — нужно опуститься ниже `target`). Поле `initial` записывает указанное значение в scoreboard в момент загрузки задачи.

### `predicate` — предикат Minecraft

```json
{
    "type": "predicate",
    "predicate": "example:has_key"
}
```

Бинарное условие, прогресс-бара нет.

### `all` / `any` / `none` — составные условия

```json
{
    "type": "all",
    "conditions": [
        { "type": "score", "objective": "gold_collected", "target": 100 },
        { "type": "predicate", "predicate": "example:has_key" }
    ]
}
```

- `all` — выполнено, когда выполнены **все** подусловия. Прогресс-бар: число выполненных подусловий.
- `any` — выполнено, когда выполнено **хотя бы одно** подусловие. Прогресс-бара нет.
- `none` — выполнено, когда **ни одно** из подусловий не выполнено. Прогресс-бара нет.

Условия вкладываются друг в друга без ограничений.

### `tasks` — статус других задач квеста

```json
{
    "type": "tasks",
    "tasks": ["side_task_a", "side_task_b"],
    "status": "success",
    "count": 1
}
```

- `tasks` — список task ID того же квеста. Если не указан или пуст — используются все задачи активного этапа.
- `status` — ожидаемый статус (`"success"`, `"failure"`, `"skipped"`). Если не указан — засчитывается любой терминальный статус.
- `count` — минимальное число задач с нужным статусом. Если не указан — должны совпасть все задачи пула.

Если цель больше 1 — отображается прогресс-бар.

## Кнопки ручного завершения

Альтернатива автоматическим условиям — игрок завершает задачу сам, нажимая кнопку прямо в квестовой книге:

```json
{
    "tasks": {
        "choose": {
            "title": "Сделай выбор",
            "buttons": ["success", "failure", "skip"]
        }
    }
}
```

Допустимые значения: `"success"`, `"failure"`, `"skip"`. Порядок в массиве не важен — в книге кнопки всегда отображаются в порядке success → failure → skip. Сервер проверяет авторитетно, что задача активна и не завершена. `buttons` и `condition` независимы и могут использоваться одновременно.

## Хуки жизненного цикла

К каждой задаче можно привязать функции датапака и scoreboard-теги:

```json
{
    "tasks": {
        "my_task": {
            "on": {
                "load":        { "functions": ["example:on_load"],   "tags": ["task_started"] },
                "tick":        { "functions": ["example:on_tick"] },
                "pinned_tick": { "functions": ["example:on_pinned_tick"] },
                "unload":      { "functions": ["example:on_unload"] },
                "success":     { "functions": ["example:on_success"], "tags": ["task_done"] },
                "failure":     { "functions": ["example:on_failure"] }
            }
        }
    }
}
```

| Хук | Когда срабатывает |
|-----|-------------------|
| `load` | Один раз, когда задача становится частью активного этапа |
| `tick` | Каждый тик, пока задача в активном этапе и не выполнена (для **всех** активных квестов) |
| `pinned_tick` | То же, но только пока квест **закреплён** в HUD |
| `unload` | Один раз, когда задача перестаёт быть активной |
| `success` | При успешном выполнении задачи |
| `failure` | При провале задачи |

В каждом хуке оба поля (`functions`, `tags`) необязательны.

## Зависимости и разблокировка

Квест можно заблокировать до выполнения других квестов через поле `after` — список **групп**:

```json
{
    "after": [
        ["story:ch1_a", "story:ch1_b"],
        ["story:ch1_c"]
    ]
}
```

AND внутри группы, OR между группами. Квест разблокируется, когда все квесты хотя бы в одной группе завершены успешно.

Дополнительные условия через `require` — проверяются вместе с `after` в момент завершения зависимости:

```json
{
    "after": [["story:prologue"]],
    "require": {
        "tags": ["found_secret_passage"],
        "predicate": "example:is_nighttime"
    }
}
```

`require` без `after` игнорируется. Ручная выдача командой `quest give` зависимости и `require` не проверяет.

## Повторяемые квесты

```json
{ "repeatable": true }
```

Завершённый repeatable-квест можно выдать игроку снова — прогресс предыдущего прохождения сбрасывается автоматически. Активный (незавершённый) квест перевыдать нельзя независимо от флага. Полезно для дейликов, фарм-квестов и сезонных ивентов.

## HUD и книга квестов

**HUD** — закреплённые квесты отображаются в углу экрана. Для условий с прогрессом показывается прогресс-бар, появление/исчезновение и смены этапов анимированы. Одновременно может быть закреплено несколько квестов; внутри каждого видна одна задача активного этапа.

**Книга квестов** — открывается клавишей `J` или ПКМ по Quest Book. Список активных и завершённых квестов с деталями, загружаемыми с сервера. Задачу можно закрепить прямо из книги.

**Уведомление о новых квестах** — если квест выдан игроку, но не виден (не закреплён в HUD и книга закрыта), на HUD появляется тост «У тебя N новых квестов — нажми [J]». При одном квесте клавиша открывает книгу сразу на нём.

**Закрепление при выдаче** управляется флагом `pin_mode`:
- `auto` — закрепить, если ничего не закреплено (по умолчанию)
- `force` — закрепить всегда
- `off` — не закреплять автоматически

## Предметы

### Quest Book

Книга квестов — внутриигровой предмет. Крафтится в произвольном расположении из:

```
minecraft:book + minecraft:rotten_flesh + minecraft:string
```

Открывается ПКМ или клавишей `J`. Рецепт можно переопределить или отключить через датапак (`data/travelcorequesting/recipes/quest_book.json`).

### Quest Scroll

Расходуемый свиток, привязанный к конкретному квесту через NBT-поле `Quest`. При ПКМ выдаёт игроку квест и автоматически открывает книгу на нём. Кулдаун 1 с защищает от двойного срабатывания. Рецепта крафта нет — раздаётся через лут-таблицы, торговцев или команду:

```
/give @s travelcorequesting:quest_scroll{Quest:"story:rescue_blacksmith"}
```

Стак до 16 штук; стаки с разными квестами не объединяются.

## Gamerules

### `doQuestBookItemCheck` (default: `false`)

Когда `true` — клавиша `J` и Quest Scroll работают только если у игрока в инвентаре есть предмет Quest Book. ПКМ по самой книге gamerule не затрагивает (книга уже в руке). Полезно для карт, где квестовая система — часть выживания.

### `allowManualQuestPin` (default: `true`)

Когда `false` — игрок не может вручную закрепить или снять задачу через квестовую книгу. Команды `quest pin`/`unpin`, авто-пин при выдаче зависимого квеста и системный пересчёт при смене этапа правилом не затрагиваются.

## Справочник команд

Все команды требуют уровень оператора **2+**.

### Управление квестами игрока

| Команда | Описание |
|---------|----------|
| `/quest give <player> <id> [pin]` | Выдать квест игроку |
| `/quest drop <player> <id>` | Забрать квест (прогресс теряется) |
| `/quest pin <player> <id> [taskId]` | Закрепить квест/задачу в HUD |
| `/quest unpin <player> <id>` | Открепить квест из HUD |
| `/quest complete <player> <id> task <taskId> success\|failure\|skip` | Выполнить задачу |
| `/quest complete <player> <id> stage success\|failure\|skip full\|required` | Выполнить задачи активного этапа |
| `/quest complete <player> <id> success\|failure\|skip full\|required` | Выполнить весь квест |
| `/quest purge <id>` | Снять квест со всех игроков (включая оффлайн) |

### Создание и редактирование (только динамические квесты)

| Команда | Описание |
|---------|----------|
| `/quest new <id> [title] [desc]` | Создать квест |
| `/quest remove <id>` | Удалить квест |
| `/quest modify <id> title <text>` | Изменить название |
| `/quest modify <id> description <text>` | Изменить описание |
| `/quest modify <id> tasks add required <taskId> ...` | Добавить обязательную задачу |
| `/quest modify <id> tasks add optional <taskId> ...` | Добавить необязательную задачу |
| `/quest modify <id> tasks remove <taskId>` | Удалить задачу |
| `/quest modify <id> icon <item>` | Установить иконку |
| `/quest modify <id> index <n>` | Установить порядок сортировки |
| `/quest modify <id> repeatable true\|false` | Повторяемость |
| `/quest modify <id> pin_mode auto\|off\|force` | Режим автозакрепления |

### Просмотр и проверка

| Команда | Описание |
|---------|----------|
| `/quest list [all\|static\|dynamic]` | Список всех квестов |
| `/quest list trackedby <player> [статус]` | Квесты игрока с фильтром по статусу |
| `/quest list tasks <id> [all\|required\|optional\|unused]` | Задачи квеста |
| `/quest test <player> <id> <статус>` | Проверка статуса (возвращает 0 или 1) |
| `/quest query <player> <id> stages complete\|total\|percent` | Числовой прогресс по этапам |
| `/quest query <player> <id> stage active\|<n> tasks complete\|total\|percent` | Числовой прогресс задач этапа |
| `/quest query <player> <id> task <taskId> success\|failure value\|target\|percent` | Числовой прогресс условия задачи |

**Статусы:** `active`, `complete`, `succeeded`, `failed`, `skipped`, `pinned`

`/quest query` совместим с `/execute store result score` — удобно для скорбордных механик.

### Интеграция с `/execute`

```
/execute if quest @s example:escape succeeded run say Квест пройден!
/execute unless quest @s example:escape active run ...
/execute if task @s example:escape push_the_lever succeeded run setblock ~ ~ ~ air
```

## Для разработчиков

### Сборка

```bash
./gradlew build
```

### Структура

```
src/main/java/k4k/travelcorequesting/
├── domain/          # Доменные модели (Quest, Task, условия)
├── questing/        # Бизнес-логика (менеджер, трекеры, события)
├── infra/           # Инфраструктура (команды, сеть, сериализация)
├── client/          # Клиентская часть (HUD, экраны, анимации, уведомления)
└── common/          # Общие утилиты
```

### События

`ServerQuestManager` публикует события на каждом шаге жизненного цикла квеста — другие моды могут подписываться через `QuestEvents` и `QuestProgressEvents`.
